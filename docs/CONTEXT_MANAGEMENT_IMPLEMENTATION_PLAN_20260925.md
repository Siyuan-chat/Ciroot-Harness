# Harness 统一上下文管理：细化落地方案

日期：2026-09-25。状态：**方向通过；本文件补齐实施契约，C0–C4 仍须逐阶段授权、实现和验收**。本文不表示功能已实现或通过验收。依据用户提供的两轮 Pro 设计意见及当前 D18 RAG、D19 调查与 GUI 对话代码制定；现有能力与工作树状态须在 C0 重新读回。当前工作树存在大量未提交的用户/其他任务修改，实施时以当时的实际文件为权威输入，不重置或覆盖。

## 1. 目标与停止边界

目标是在已有 `InvestigationService`、`RagLibrary`、GUI `ConversationStore` 和模型适配器之间增加一套共享的上下文装配契约，使每次模型任务能回答：获准读取什么、实际装入什么、遗漏什么、输出依据什么。原始文献、对话与任务结果继续本地持久化；模型调用只接收任务所需内容。跨角色传递稳定引用和结构化产物，不传递彼此完整聊天历史。

本方案先交付可复现的单工作区、单库、单 run 上下文链，再扩展目录导航。保留既有五项 RAG 公共接口和已有调查、GUI 协议；新增能力使用版本化扩展。首轮不做全局“永久驻留”模型记忆、第二套 agent/状态机、专利全族 claim graph、自动法律新颖性判断、跨库联合检索、GUI 重设计或付费真实案例。现有冻结 run、报告、原文、旧证据行与 23 篇参照库均只读；新增映射和修订记录只写在获准的新 schema 或隔离工作区中。

## 3. 统一对象与不变量

使用已有工作区 SQLite 和被 Git 忽略的原文/产物目录，不另建平行业务库。下列名称是逻辑对象；实现可用新增表或关联记录，但公共 JSON 字段与语义保持一致。

| 对象 | 身份和内容 | 生命周期 |
|---|---|---|
| `RunSnapshot` | `run_id`、`spec_hash`、初始参照文档/版本成员、工作区/库/集合身份、来源及模型数据政策、预算上限 | 启动时冻结。后续修改建新 run 或显式修订，不回写旧快照 |
| `RunStateRevision` | `run_id + state_revision`、已执行查询/来源尝试、当前工作语料成员、Finding、缺口、人工决定的不可变版本引用及当时预算账本位置 | 在既有 run 事务边界递增；任何能进入 bundle 的可变对象都必须能按绑定修订读回。历史预算只供解释，不代表当前可花额度 |
| `CorpusRevision` | 参照快照指纹 + 本 run 已正式接入的 discovery 文档/原始版本/解析修订有序集合 | 新资料接入形成新修订；规划、分析和报告绑定所读修订；旧任务不追随后来新增资料 |
| `ParseRevision` | 原始 `version_id` + 源哈希 + 解析器/配置/模型版本指纹 + 解析产物哈希 | 同一原始文件重解析生成新修订；旧证据与 locator 保留并可按旧修订读回 |
| `RetrievalTrace` | 查询及修订、授权语料/scope、检索与重排配置、候选顺序、选择及结构展开、已知未选候选 | 扩展既有查询/结果记录，逐次不可变；重编译旧输入读取已保存选择，绝不暗中重搜 |
| `ContextManifest` | 指定 scope、角色、状态修订和语料修订下生成的导航节点及版本哈希 | C2 先用固定引用清单；C3 加结构目录。派生缓存可重建，描述只用于导航，不充当科学证据 |
| `ContextBundle` | 任务约束、局部目录、选定原文、结构上下文、已核查决定、缺口及输出 schema | 每次调用冻结；包含项与遗漏项均有稳定引用 |
| `ContextReceipt` | bundle、编译规则、身份/权限、实际装入/遗漏引用、完整逻辑请求、捕获层和发送状态 | 每次受控模型调用或 host payload 交付单独持久化；证明 harness 可观察的行为，不证明模型已理解 |

`RunSnapshot` 中保存当时的授权范围用于审计；每次读取与外发还须通过**当前有效权限 ∩ 快照授权 ∩ 任务需要 ∩ 目标执行器发送权限**。撤权后，即使旧 bundle 曾存在，也不能用目录、缓存、摘要或旧 artifact 绕过 harness 控制范围内的后续读取与外发；已经交付外部宿主或导出的内容无法追溯撤回。`workspace_id/library_id/collection_id/run_id` 全部在服务端绑定，不让模型选择任意路径或扩大 scope。

## 4. 数据契约与写入规则

### 4.1 稳定证据地址

新证据地址至少含 `library_id`、`document_id`、原始 `version_id`、`parse_revision_id`、`evidence_id`、`locator` 和 `source_sha256`。PDF locator 保留物理页与 bbox/表格坐标体系；专利 XML 优先保留具体公开文本身份、claim/paragraph ID 或 XPath。家族 ID 仅用于关联导航，不替代某一公开文本的引用。旧证据缺 `parse_revision_id` 时，以已有 `rag_versions.parser`、旧证据集合和源哈希形成一次性 `legacy` 修订映射；无法确定的记录标为 `unresolved_legacy`，不猜测位置。legacy 映射只保全**当前仍可验证**的对应关系，不追认已经丢失的历史定位。C1 先用一致性数据库备份建立隔离副本，演练新增表/映射；获准后也只追加新记录，旧证据行、源文件和报告保持不变。

新增结构节点使用 `node_id`、`parent_id`、`node_type`（document/section/claim/paragraph/table/example 等）、`document_id`、`version_id`、`parse_revision_id`、locator、`availability`、`coverage`、可选导航描述。结构节点的范围不能跨不同公开文本或解析修订。优先确定性解析 XML 结构和 Docling 标题/表格；解析不可靠时保留扁平证据与局限标记，不由 LLM 编造章节。

### 4.2 状态和任务的读版本

**依赖满足、形成可执行的 `task_version` 时**，在同一事务内绑定 `run_snapshot_ref`、`state_revision`、`corpus_revision`、角色及能力要求。提前存在的工作流节点不等于已冻结的执行版本。当前任务若本来就在依赖完成后才创建，则沿用其时点。新材料影响旧任务时，创建有出处的新任务版本，不回写已冻结版本。

历史可读性采用**不可变对象版本 + 修订成员表**：对可能装入 bundle 的 Finding、人工决定、查询结果、缺口、资料成员和其他可变业务对象，在任务冻结时保存内容哈希与不可变版本引用；`RunStateRevision` 指向这些版本。读取旧修订只解析该表中绑定的版本，不能从被覆盖的当前行取值。现有事件账本用于核对沿革，不假设它已能完整重建旧正文。若某历史对象无法证明旧值，标 `historical_context_unavailable`，不可用当前值补写。实现者在 C0 列出对象清单及写入事务边界，C2 用跨重启的旧/新 Finding 读回测试证明该契约。

旧快照中的预算余量仅解释当时判断；每次可能计费的发送前，仍按**当前持久账本**原子预留额度，并重查当前权限与能力。编译器按绑定引用取数，不用“当前最新版”替换旧任务输入。原文/解析产物不可取、权限撤销或能力未验收时，任务进入可读的 `context_unavailable`/`policy_blocked`/`capability_pending` 状态，不自动改读其他版本。

会话消息仍由 `ConversationStore` 完整保存。调查启动前的自然语言需求尚无 `run_id`：C3 使用服务端绑定的 `workspace_id + conversation_id + spec_draft_revision` 作为入口，复用同一引用解析、权限和收据规则；到 C3 验收前，“统一”只覆盖调查任务。规划时保留最近消息作为一个入口，同时可按消息 ID 读取相关早期原话；历史提炼的需求附消息 ID。用户修改研究范围只形成待验证的 `ResearchSpec` 候选，不能直接改写运行中的 `RunSnapshot`。

### 4.3 检索选择、重放与覆盖

每次真实搜索或重排扩展既有查询/结果记录为不可变 `RetrievalTrace`：`retrieval_id`、查询/修订、允许的 corpus/scope、检索配置指纹（索引、分词、向量/重排模型及排序规则）、候选 ID/版本/顺序、选定证据与结构范围、已知未选候选及原因、执行状态。**恢复旧 bundle 只重放已保存的选择与指定版本原文；重新搜索必须产生新 trace。**冻结语料并不保证共享索引或统计变化后的排序相同。先按冻结 scope 限制候选再取 top-k，禁止全库 top-k 后过滤旧语料。C2 不要求保存每版完整向量库，只保证旧选择和正文可重放；算法级完全复现另报告所需索引和配置条件。

`omitted_refs` 仅指**当时已知候选**中未装入的对象。`searched_scope` 记录实际检过的库/文档/章节、版本和方法；`loaded_scope` 记录送入此次调用的原文；`verified_scope` 记录完成定位、引句及主张支持检查的范围。未检索、未解析、仅题录、索引不全和来源失败分别作为覆盖缺口；不得从 top-k 空结果推断全文或全库不存在。

### 4.4 调用收据与实际请求

受控 API 模式区分 `task_id/task_version`（研究任务和冻结输入）、`invocation_id`（使用一个 bundle 的逻辑调用）和 `attempt_id`（该调用的一次具体发送尝试）。工具返回保存稳定 `tool_result_id`；后续调用如果装入该结果，必须在自己的收据中引用。host/外部 agent 只记录可见 `delivery_id`，不虚构不可见的 `invocation_id`。

`ContextReceipt` 最小字段：上述身份、`role`、`run_snapshot_ref/state_revision/corpus_revision`、`retrieval_ids`、`manifest_hash`、`compiler_version`、`model_profile_ref`、`included_refs[{ref,usage,version,locator}]`、`omitted_refs[{ref,reason}]`、三类覆盖、`logical_request_ref/hash`、可选 `transport_body_hash`、`capture_layer`、`body_capture`、输入大小/估算方法、`policy_result`、创建时间及状态事件。`usage` 区分 task_constraint、primary_evidence、counter_evidence、background、prior_decision、navigation；目录 ID 仅为 navigation 时不计入已读原文。因权限拒绝的对象仅进受保护的内部审计记录，模型可见遗漏说明不得泄露其标题或其他受限元数据。

API 模式在政策检查后、发送前保存**完整应用层逻辑请求**：系统/角色指令、消息、工具与输出 schema、模型参数及适配器加入的内容；对固定序列化规则和版本计算 `logical_request_hash`。若只保存 SDK 入参，`capture_layer=application`，只声称应用层内容一致；只有在客户端传输边界实际捕获最终发送体字节时，才记录 `transport_body_hash` 并声称字节一致。JSON 语义相同但字节可能不同。外部附件或远端会话状态须绑定可读内容版本，否则标重放限制。`created_at`、审计 ID 等放收据，不无故注入模型输入。鉴权头、密钥和环境变量值绝不入库。

发送账本使用追加状态事件：`prepared`（内容和收据已落盘）、`dispatching`（已进入发送过程）、`response_received`、`outcome_unknown`，以及结果提交/失败的终态；**prepared 不表示请求已发出**。统一账本控制重试，底层客户端或 SDK 的隐藏重试须禁用或显式计入 attempt。结果不明时不自动再次发出可能计费的调用；服务端实际执行与费用以可取得的服务端记录为准，不作本地“未计费”保证。响应提交、Finding 写入和预算结算用调用/尝试 ID 幂等，重复回调不产生第二份结果。不能安全保存保密正文时标 `body_capture=restricted` 与缺失原因，不为重放扩大留存。

host/外部 agent 模式只能记录 harness 提供的任务 payload、工具响应及其哈希；宿主最终系统提示、其他工具内容和模型内部上下文不可见，收据标 `visibility=harness_payload_only`。GUI managed MCP 同理。不得把“工具返回已送达”表述为“宿主模型一定看过且理解了原文”。

### 4.5 派生关系与存储保护

`evidence_refs` 表示主张的科学支持；`derived_from_refs` 表示查询、目录描述、摘要、Finding 或报告从哪些输入产生。权限与外发沿派生关系传递，派生产物默认继承输入中最严格的适用限制；降低限制需有可追溯的人工确认或已批准转换。内部资料提炼出的术语即使不作为引文，也不能自动进入外发专利检索式。

`.gitignore` 不是访问控制。保存请求体、bundle 和收据的目录需限定当前用户/服务进程权限，由服务端鉴权控制读取；导出、日志和备份沿用来源限制，不在浏览器持久层、普通日志或 Git 产物中泄漏。C0 记录当前本地存储和备份机制；没有已验收加密能力时不宣称“加密存储”。

### 4.6 核查结果的三个层次

每条主张分别记录 `locator_check`（文档、原始版本、解析修订及位置）、`quote_check`（引句与指定原文一致）、`support_check`（主张的条件、范围、不确定性是否受原文支持）；各项含 `status`、`method=rule|model|human`、输入版本和失败原因。引句子串匹配只属于第二层，不自动使第三层通过。C2 建立类型与失败路径，不承诺自动科学语义核查已达标；C4 在有支持、反证、遗漏条件与证据不足的样本上评价。单个 `verified=true` 不作为下游放行依据。

### 4.7 调用输入选择与重放（C2a）

同一 `task_version` 可有多次模型调用。**在编译前**为每次 `invocation` 冻结 `task_version_ref`、`retrieval_ids`、按顺序排列的 `tool_result_ids`、`selected_input_refs` 和 `compilation_profile_ref`。配置引用绑定角色模板、工具与输出 schema、预算规则及序列化版本。编译器只解析这份选择，不在重放时自行纳入后来生成的工具结果、换模板或调整排列；需要新选择就创建新的 invocation。固定测试：同一任务产生两个工具结果后，重放第一次调用仍只含其当时已选的结果。

### 4.8 SQLite 与文件产物的发布协议（C1–C2a）

原文副本、解析结果、bundle 和请求体先写入临时文件，完成后计算内容哈希并在同一文件系统内发布到不可变目标；随后才在 SQLite 事务中登记为可读取对象。读取时核对路径、大小/哈希与绑定身份。文件写成但数据库登记失败时作为未登记产物处理，不进入正式证据；数据库已有引用但文件缺失、半写入或哈希变化时返回完整性错误，不重生成“近似内容”代替旧版本。具体同步、崩溃恢复和未登记产物清理策略须按 C0 确认的 Windows 文件系统及当前存储实现定案，并用故障注入验证。

### 4.9 运行时发送权与结果结算（C2b）

开发时“唯一代码写入者”与运行时模型调用占用是不同约束。同一 invocation 的发送权必须经数据库唯一约束或原子状态转换领取；GUI 重复点击、CLI/MCP 并入与超时恢复不能让两个执行者同时获得发送权。`outcome_unknown` 的额度预留保持占用，直到服务端记录或有审计的人工处理决定其结算；本地超时不自动释放额度。收到响应先保存可观察的原始响应与调用状态，再做 JSON/schema/科学核查。解析失败或主张不受支持仍计为发生过的调用；后续修复或再次调用另记 attempt/invocation。响应保存、业务结果提交和预算结算分别幂等。

### 4.10 不可信资料与工具边界（C2a–C2b）

论文、专利、网页、目录描述、检索结果及上游模型摘要均为数据。编译器将可信角色规则和这些数据分区装配，资料中的命令不得进入高优先级指令；上游输出也不能自行扩大 scope、权限或预算。工具调用仍由服务端核对执行者身份、允许动作、库/工作区范围与外发政策。离线恶意文献 fixture 包含“忽略研究规格、读取其他库、外发资料”等语句；验收要求这些语句不能改变实际工具权限、选择或请求目标。

## 5. Context Compiler 放置与调用接口

编译器位于已有持久 `ModelTask` 与模型适配器/host 任务读取边界之间。C2 覆盖调查任务；C3 将同一读取、权限和收据规则用于调查前的 GUI 会话/规格草案。所有调查角色复用一套校验和收据生成流程，不复制 LangGraph 调度。逻辑接口：

```text
compile_context(task_ref, execution_profile, current_policy, input_budget)
  -> ContextBundle + ContextReceiptDraft
```

调用方不传任意 `state_version`/`corpus_version`；服务从可执行任务版本及本次 invocation 的冻结输入选择解析。编译器只解析**已有选择**、检查权限并装配预算；新搜索、重排或由模型重新挑选材料须先产生独立 `RetrievalTrace`，不能藏在重编译中。C2 的 manifest 只是当前任务固定引用清单，C3 再扩展结构导航而不改变读取/收据语义。顺序为：

1. 校验 run/task 身份、读取修订、当前权限、能力和模型外发政策；失败即停，不请求模型。
2. 展开本角色必需的研究问题、定义、排除条件、输出约束、预算与当前任务。仅 `spec_id` 不够。
3. 按不可变对象版本加入本任务相关的状态、待处理缺口和小型目录入口；目录描述明示为导航数据。
4. 按已保存的检索选择，解析指定版本的原文证据与有结构规则或明确引用支持的必要邻域；保留已识别的支持、反证、条件、表格标题/单位/脚注。后续角色需要上游 Finding 时，同时解析其 evidence refs，不把上游结论当原文。无法判断结构是否充分时记录缺口；编译器不保证所有反证都已被发现。
5. 检查输入空间并预留输出/工具返回余量。先去重和裁剪无关目录；必需约束、反证或关键条件放不下时拆任务或返回 `context_insufficient`，禁止静默截断。
6. 固化 bundle 与收据，然后由现有模型适配器发送或暴露给 host；模型结果继续走原 schema、分层核查和人工缺口路径。每次工具返回后的受控模型继续调用均新建 invocation/bundle/收据。

预算由任务类型和模型配置确定，可用适配器 tokenizer 做估算；估算和实际 provider usage 分开记录。没有 tokenizer 时使用保守上界并明确 `estimate_method`，不把字符数当精确 token。缓存仅优化重复读取，命中与否不改变 bundle 内容、权限判断或恢复结果。

## 6. 各角色的默认上下文契约

| 角色/阶段 | 必须可见 | 按需读取 | 禁止隐式继承 |
|---|---|---|---|
| 规划 | 冻结研究问题、范围/排除、来源许可、预算、参照证据出处、既有查询/缺口 | 术语原文与相关历史需求消息 | 其他角色完整聊天、未获准外发的内部资料 |
| 来源/候选筛选 | 已批准查询、来源语法/范围、去重键、请求账本与失败 | 候选题录/可用正文状态 | 参照库全部原文、未批准查询扩写 |
| 分析/业务判断 | 明确子问题、定义、候选原文、必要条件/反证、文档覆盖 | claim 引用链、表格上下文、实施例条件 | 只含上游结论而无原文的输入 |
| 综合/写作 | 报告规格、已核查 Finding、每项主张的原文引用、冲突与缺口 | 指定证据包和人工决定 | 全量检索碎片、未核查的模型摘要作为事实 |
| 核查 | 待核查主张、绑定版本的原文、定位与覆盖记录 | 原文件/结构邻域和反证 | 单靠上一阶段 `verified` 标签放行 |

每个角色只获得已验收能力允许的对象。题录可支持规划候选，不能支持“全文已披露”的结论；解析失败的表格只提供页面位置和缺口。`NOT_FOUND` 代表有界检索未命中；只有明确的文档集合、章节范围、版本、搜索方式及处理覆盖均记录后，才可表达“在已检查范围内未发现”，不能推成全库或法律意义上的不存在。全库数量/分布由有分母和快照的结构化查询产生，不以 top-k 命中充当全库覆盖。

### 必做验收用例

1. **历史读回与版本漂移**：Finding 更新后，旧任务跨重启仍读到旧 Finding；同源字节更换解析配置后旧 evidence/locator/报告仍可读，新任务引用新解析修订；不存在 ID 碰撞或静默替换。
2. **检索重放**：冻结 corpus 后修改共享索引/分词或加入新文献，旧 bundle 的选择和顺序从 `RetrievalTrace` 重放且不触发搜索；重新检索产生新 ID，候选先按 scope 过滤再排名。
3. **权限与派生**：撤权或切换工作区后，正文、目录描述、缓存、旧 bundle 及派生报告均在 harness 控制的入口拒绝不合格读取；内部资料派生术语不得默认外发；模型可见遗漏说明不泄露受限元数据。
4. **调用真实性与未知结果**：API 逐 invocation/attempt 核对逻辑哈希；只有实际捕获传输字节才核对字节哈希。模拟 prepared 后崩溃、发送超时、未知结果和重复回调；host 只声明可见 delivery。目录出现但未装入原文的证据不计已读。
   同任务两个工具结果的测试还须证明第一次 invocation 的重放不会纳入第二次才取得的结果；文件已写但未登记、文件已登记却缺失/篡改时分别验证不发布与完整性失败。
5. **重启与增量**：任务从冻结引用恢复；新资料形成新 corpus revision；旧历史预算不能新增支出，当前账本原子预留；结果不明的收费请求不自动重发。
6. **检索与科学边界**：目录误分仍可跨目录命中；摘要、图片/表格解析失败、冲突证据产生明确缺口；定位、引句和主张支持各自报告，通过前两项不能推定第三项。
   恶意文献 fixture 中的越权读取、扩大预算和外发命令均不得改变服务端允许动作或请求目标。
7. **规模与成本**：逐步增加文档/消息数，记录 bundle 大小、已知遗漏原因、三类覆盖、召回/定位、请求及输出用量；全库统计使用有分母的集合快照，不用 top-k 代替覆盖。

评价指标分别报告必要证据召回、版本/定位准确率、主张支持判定、缺口识别、重启复现、权限拒绝和调用成本。代码测试、真实宿主可见性与科学案例评价分层陈述；固定离线样本通过不等于真实模型输出质量通过。C0 必须列出各验收样本实际包含的考点，不能让“用一篇专利测试”隐含其覆盖全部结构情况。
