## 获得凭据后的执行计划（2026-09-24）

### 第一批：可安装的 EPO 来源与离线协议测试

Terra 负责一个固定候选：provider 的认证复用、检索/族/正文获取；runtime 与公共/包内 schema；正常 InvestigationService 分发；请求预算与脱敏记录；XML 规范化与查询历史导出。现有 epo_search 如仍有调用者须保持兼容或同步迁移，不能新增一条脱离正常服务的案例专用流程。

Luna 在接口合同确定后负责本地凭据启动器与运行脚本。DPAPI 只属于 Windows 本地启动层，通用 Python 包仍从命名环境变量读取凭据。私有密文不随包、Git 或任务载荷分发。无须构建通用密钥管理系统。

验收代表性场景：EPO-only runtime、缺凭据、不支持来源、认证失败、限流、空成功结果、分页截断、总预算耗尽；同族不同公开版本不合并；缺 claims/description 有状态；XML 引文 locator 可回查；查询导出重开保持一致。以 synthetic 协议夹具自测，不能记作 live 验证。回归仅覆盖受改动的 OpenAlex、事实 attach 和导出路径。

提交物：固定代码候选、新 wheel、可复现自测摘要、脱敏配置样例。Astra 集中审阅后，必要修正直接回传，实现者自检后再交候选，不边写边验。

### 第二批：两请求起步的真实探针

批准运行预算后，Luna 在真实联网身份启动隔离安装物：先本地解密/模块路径检查，失败时不发网络请求；成功后一次认证、一次 Q1 首页面检索。两次请求均计入原 20 次总账。

只输出认证成功与到期信息、HTTP 状态、请求 ID/查询式/页范围、候选身份及覆盖，不输出 token 或密钥。401/403 停在认证/权限层诊断，不能自动切换网站或再建 run。成功的查询页持久化，完整闭环复用同一 run/缓存与预算，不重复进行相同 smoke 检索。

### 第三批：单族 XML 与论文对照

在剩余查询额度内完成候选筛选，保留排序与未选理由；选择一个有来源支撑的族及最多两份公开文本。从实际来源区分 simple/extended family 的语义，不把两种族编号混为同一标识。

保存 XML 原件和版本身份；claims、description、实施例分别标注，表格若无法准确保留条件与数值关系则标缺口。导入独立发现库，用公共 attach 让新证据与 P3 已验收论文证据共同进入分析。当前 attach 有 OpenAlex 专用绑定，必须验证专利身份映射后扩展，不能用虚构 DOI 或伪装 OpenAlex 文档绕过。

进入分析前检查新旧事实均可引用；进入写作前检查主张、条件和来源支持，之后生成中文技术调查报告与主题综述。查询记录由真实执行轨迹机械导出，科学解释由角色生成。批量筛选先检查已有 Jev 访问配置；没有访问或外发授权时回退既有宿主筛选路径，不因此阻塞全部来源接线，也不把科学分析委托给分类 API。

### 第四批：最终验收与收口

Astra 审阅固定候选的两份中文正文、逐条正式主张/引文、选族依据、XML 定位及检索历史。最短追溯链必须成立：原始 CQL → 实际请求/页 → 候选 → 所选公开版本 → 证据 → 主张 → 正文。

重开只读状态并复导出，原库/旧报告保留、预算不增加、无新增请求。交付现有八个标准导出及 search-strategy.zh-CN.md、search-history.json，共十个目标文件；若格式/章节缺失则如实报告。通过后停止本阶段，不追加 GUI、监测、三语全评价或 GitHub 推送。

计划审批对象为本文件执行顺序及 D19_P4_PLAN.md 第4节总预算：20 次 OPS HTTP、20 MiB、10 个服务任务、14 次宿主生成及修订；一族、两公开文本、XML优先且本轮不下载PDF。失败与重试占原额度，耗尽后保存 partial 并集中报告。仅凭账号批准、密文保存成功不宣称 API 接入完成。
