日期：2026-09-24。状态：已执行第三个有界真实 run；同 run 双新正文证据链通过独立核查，标准公共导出未通过，run 因检索覆盖保持 `partial`。当前收尾与下一步见 [D19_QUERY_LOOP_STAGE_HANDOFF.md](D19_QUERY_LOOP_STAGE_HANDOFF.md)。权威起点为 [D19_RAG_QUERY_LOOP_HANDOFF.md](D19_RAG_QUERY_LOOP_HANDOFF.md)。

## 交付与边界

在一个新调查 run 中，从只读参照库的实际 RAG 命中生成有出处的 OpenAlex 与 EPO OPS 查询；两来源分别检索、必要时按证据缺口有界修订；各取一份可用新论文/专利正文并导入独立发现库；形成可回溯的中文技术调查报告、主题综述与检索历史。没有正文或预算耗尽时如实交付 `partial`，不补造结果。旧 P3/P4 run、原文、库与报告保持冻结。

本阶段不开发 GUI、监测、法律判定、全面 OCR、额外来源或 GitHub 发布。只改调查主链直接受影响的源码、对应 schema、新增离线测试与本计划/决策记录；需要其它路径时先取得用户明示批准。现有 P4 未提交修改是保留输入，不能被清理或覆盖。

## 执行分工与顺序

1. Luna 只读核对 P4 固定候选的独立验收状态，另在独占的新测试文件准备最小离线协议/故障测试。Terra 是产品源码唯一写入者，复用 `RagLibrary`、既有任务、查询、预算、来源和发现证据接口。两者自测后交固定候选；我只对固定候选独立验收并合并一次反馈。
2. 本地 RAG 检索结果随 planning task 持久化，包含稳定 evidence ID、文档/版本及原文 locator。查询 `input_refs` 必须指向实际命中；术语/限制依据有可核对的原文支持。没有足够命中时明确缺口，不把手工种子说成 RAG 生成。
3. 同一 run 的 OpenAlex/OPS 查询和修订复用现有持久任务与预算；来源语法分别校验，父查询、原因和证据引用入历史。失败、认证、重试、页与正文请求均计入总账；恢复/复导出不新增请求。
4. 新论文和专利各自保存不可变原文/版本并导入独立发现库，通过公共 attach 进入正式事实。报告区分论文实验、专利权利要求、说明书及实施例；数字、单位、条件和引用由原文核对，不可比与图表缺口保留。
5. 先用离线 fixture/协议测试及隔离 wheel 安装证明公共入口。真实小样须先批准下列上限，再以一个新 run 执行；不另开免费探针 run。实现者自测和独立科学核查分开记录。

| 搜索页/候选 | 每式最多 1 页、每页最多 5 条；各来源最多保留 10 个唯一候选 |

上述是硬停止上限而非预期用满额；命中不足不自动增加额度、来源或 run。模型服务账单和数据源潜在费用分别记录，未知用量不写成零。外发仅限获准的公开查询与必要证据片段；实际查询及模型输入在调用前检查现有数据策略。若已缓存的公开正文可合法复用，保留真实来源与版本记录，减少实际请求，但不得用旧 P3/P4 成果冒充新 run 获取与入库。

## 独立验收

- 一条实际执行查询的非空 `input_refs` 连到本轮真实本地 RAG 命中、正确文档版本和 locator，术语/限制与原文相符；两来源语法各自成立。
- 同一 run 的历史能连起本地证据、两来源查询/必要修订、请求/候选、论文及专利新版本、发现库 RAG、findings/claims 和中文双正文。无修订需求时不为了演示额外发请求，离线测试覆盖修订分支。
- 关键原文、数值、单位、条件及主张支持独立核对；重开/复导出不联网；P3/P4 冻结资料和只读参照库未变。代码测试、正常服务、科学准确性分别给出结论。
