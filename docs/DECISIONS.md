## 架构基线与可调整的工程默认值

- Python 包 + CLI / 可调用 Python API，Windows 为本地验收环境，Linux 由 CI 覆盖。
- LangGraph 编排；Docling 解析；LlamaIndex 仅 RAG 模块；Qdrant 向量库；SQLite 保存规范化业务记录。
- 首版 OpenAlex + EPO OPS；Lens 后续。模型适配先覆盖 OpenAI 兼容接口和 Anthropic，保留同契约扩展。
- 三语报告默认全部生成；对话语言默认沿用用户输入。原文语言与检索语言独立。
- 报告 HTML + Markdown，规范化 JSON 数据，人工清单另附 UTF-8 CSV。首版不增加 Word/PPT/Excel 作者工具。
- 配置完整且用户表达执行意图时可直接执行；仅“修改需求”默认保存版本，不自动产生新 API 调查费用。
- 预算默认每轮候选 50、每来源检索式 3、扩展轮数 2、模型调用 120、并发 3、活动执行 30 分钟、单文件 30 MiB、总下载 300 MiB。它们是可修改的工程上限，不是费用承诺或科学阈值。
- 货币预算默认未设置；所有运行记录调用/用量。配置估算费用上限时必须有模型计价信息，并明确它不替代服务商账单。
- GitHub 发布建议 MIT（待发布阶段定稿）；不在当前设计阶段代替用户选择仓库归属或分发私有资料。

## 变更规则

### 自动验收与修正（D13）

使用当前设计任务的 Codex heartbeat 定期跟进，实现者提交检查点后继续明确未完成的工程工作。设计任务对提交快照独立测试，在 `docs/reviews/<commit>.md` 记录证据、失败复现与状态，直接交给原 Terra 任务。复验以新提交和受影响行为为单位，已有效的证据不反复重跑；同一反馈不重复派发。具体任务标识、最后验收提交、已派发反馈和自动化标识保存在忽略的 `.local/acceptance/loop-state.json`，不进入公开产品配置。

停止条件：G1/G2 中适用于本地完整框架的验收项通过且无阻断问题，交付最终报告，通知 Terra 停止本轮工程工作，并通过应用工具暂停自动化。依赖真实凭据的在线验证、聚合物科学案例和 GitHub 发布必须单独标明待完成，不能凭夹具替代。只有外部输入缺失且已没有可继续的工程工作时才暂停并集中说明所需输入；阻塞不等于通过。

本自动化协调开发，不改变 D09 中产品由用户手动发起调查的行为。

用户后续消息累计增补要求。改变本记录的已确认行为时须说明影响；无需为例行重构、补测、公开接口适配重复询问。设计更新保留版本/日期；软件运行的 spec_revision 与设计基线 D1 是两种独立版本。
