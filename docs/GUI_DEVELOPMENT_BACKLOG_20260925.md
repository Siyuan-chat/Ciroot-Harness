### W1：新建工作区

交付：顶部及空态“新建工作区”，名称/说明、空库或一个已有只读参照库、创建并进入；后端生成稳定身份及受控数据目录，持久注册并即时更新列表。

验收：同名不同 ID、幂等重试仅创建一次、冲突明确、重启保留、空库可进入、失败无正常可见半成品、旧库/旧 run 不变。拒绝浏览器任意磁盘路径。三语控件和 F04 回归通过。

分工与范围严格沿现有 W1 合同：Terra 先单写后端和定向测试，再由 Luna 单写前端，Sol 独立验收。首版不做工作区删除、迁移。

### W2：统一操作服务与后台命令行

交付：managed CLI/MCP 薄客户端，提供 workspace/library/collection 列表、run 创建/状态/角色提交/推进/停止/恢复/导出、队列状态与证据读取。API agent 使用同一操作合同。GUI 显示同一 command/run 的真实事件；导航指令只能定位对象，不触发研究。

实现要求：复用 U09，不让 managed MCP 长期独占核心写锁；旧 standalone 模式保持兼容并受锁保护。统一 workspace/run/task_version、幂等和稳定错误。即时业务结果与异步 command_id 两种成功响应都必须处理。提供机器可读 JSON，命令参数及模型上下文不含认证秘密；后台命令不使用任意 shell 拼接。

验收：CLI/MCP 发起操作后 GUI 出现相同对象与结果；跨 scope 不串项；重复请求不重复执行；后台完成不抢当前页面；GUI 窗口关闭但 headless 服务运行时仍可操作；服务失联时明确失败。

拟定所有权：Terra 操作服务/CLI/MCP，Luna 前端状态订阅，Sol 冻结接口。若需抽取 app.py 中的共用服务，先列精确文件归属与兼容回归，不顺带重写科学核心。

### W3：对话框与自动 API Agent

交付：按工作区持久保存的对话面板；自然语言需求→必要澄清→ResearchSpec→角色执行→报告与证据卡片。用户无需填写角色 JSON。显示执行器、授权范围、调用预算、队列/等待原因与停止入口。

实现要求：复用既有 API 模型适配器、任务版本协议和调用账本；受控工具调用驱动 W2。用户只讨论时不自动发起研究，明确要求执行且范围/预算齐备时继续。对话回复、工具操作和科学 run 状态分别记录，但不新增科学状态机。重试/重启不能重做已执行工具或重置预算；密钥不存入会话；保留 partial 和证据缺口。

验收：离线 scripted executor 在对话中走完创建、全部角色、报告和原文定位；三语切换/切库不串会话；模型/工具失败不显示成功；停止回复与停止调查语义不同且有效。真实 API 小预算测试单列，离线通过不等于真实模型通过。

分工：Terra 执行器/会话工具桥；Luna 对话界面。共享消息、工具与预算合同由 Sol 先冻结。

### L1：文献导入、库与分组管理

交付：新建可写库、导入本地资料、查看解析/索引进度和失败；创建/重命名分组、增减成员、将库关联工作区。集合关系与参照/发现身份分离，已有只读库明确禁用写入。

实现要求：先核对既有 RagLibrary 公开导入接口及最终包依赖，再冻结支持文件格式；当前打包排除了部分解析依赖，不能只加上传按钮。文件经受控选择/暂存通道进入服务，不允许模型任意指定路径。导入有持久结果和可重试状态；重复资料按既有身份/版本规则处理。分组不是 PDF 或向量索引副本；移出分组不删除原文。

验收：两个实体库导入可区分资料；重复导入、同名文件、解析失败、取消/重试有明确结果；导入→索引→检索→证据/原件可定位；重启保留。分组调整不追写旧 run 冻结参照。最终 EXE 的实际解析/索引能力必须验收，不只在开发环境运行。

分工：Terra 导入应用服务、受控文件接收与依赖能力；Luna 管理与进度 UI；Sol 冻结首版格式和可写范围。删除文献/库及大规模索引迁移不纳入首版。

### R1：真实资料调查入口

交付：GUI 明确区分合成示例和真实资料调查；从已注册库/分组选择参照、填写研究问题、选择可用来源与执行器、设置来源/模型预算，再创建 live run。表单和 W3 对话调用相同创建合同。

实现要求：复用现有真实来源和模型执行代码，不能只删除 synthetic 判断。核对凭据、资料使用范围、运行配置、来源能力和参照冻结；来源禁用/失败、无全文、预算耗尽应保留 partial。配置 key 不触发检索，只有明确执行意图才创建外呼工作。报告保持真实证据身份与 locator。

验收分两层：离线注入来源/模型验证路由、预算、失败和证据流；另用明确选定真实材料与授权小预算完成用户可见调查。未获真实调用授权时交付可验收的离线路径，并将真实效果标为待验收，不自动外呼。

分工：Terra 创建/运行参数薄适配；Luna live 表单及能力提示；Sol 冻结真实样本、额度与科学验收条件。不得改旧冻结调查来制造成功案例。

### W4：外部 Codex 等 Agent 双向连接

交付：GUI 可选择外部 executor；用户消息由连接的外部 agent 接收，agent 通过 managed 工具执行后，将回复、进度和结果送回同一 conversation。

实现要求：不能以工具注册成功代替消息双向接通。单 turn 的领取、版本与确认防止重复处理；断开明确等待，重新连接不重复工具副作用。执行器切换需保留预算与已完成工作。同一任务不能被 API agent 与外部 agent 同时领取。

验收：用实际选定且可用的外部客户端完成 GUI 提问→agent 工具调用→GUI 回复/报告；客户端不存在或不支持后台唤起时明确能力缺口。通用协议离线测试和真实客户端结果分开记录。

分工：Terra managed MCP/消息桥，Luna 连接状态及 executor 选择，Sol 检查实际客户端支持与验收边界。

### X1：跨库联合检索

交付：显式多库选择及“跨 N 库”范围；各库独立检索，结果显示来源库、文档版本和覆盖；多库选择可形成冻结参照输入。

实现要求：身份至少为 library_id/document_id/version_id；不同嵌入模型或维度不共用一个索引，也不直接比较未校准原始分数。Sol 先冻结可解释合并与去重策略。无权限/不可用库保留具体缺口，不能静默变成只检索一库。多库快照逐库记录版本、成员和索引身份。

验收：两个独立库含相同 document_id/不同版本，不串证据/附件；结果来源正确；一库失败仍清楚标明不完整；切库和成员变化不改历史 run。确定性 fixture 检查身份与排序合同，真实资料检索质量另测。

分工：Terra 独立检索聚合与快照接口，Luna 范围选择和来源展示；Sol 评估科学使用边界。
