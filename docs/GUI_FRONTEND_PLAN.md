## 1. 已确认方向与本阶段结果

用户要借鉴已有开源前端代码，改造成符合本项目 harness 使用方式的独立研究工作台。首选评估 Zotero Web Library 的可复用源码；无需兼容 Zotero 服务端，也不迁移本项目业务数据到 Zotero。采用现有文献集合、列表、详情和阅读交互，增加调查、证据、人工处理和运行面板。

本阶段目标：Windows 本地可启动的 Web GUI，能浏览既有冻结调查结果，完成结论到原文定位、离线人工处理、标准导出，并用明确标识的无网络合成场景验证任务控制。真实研究 API 调用与扩大检索不属于本阶段验收。

源码评估是第一道工程门槛。若核心组件无法脱离 Zotero API 或复用成本过高，Sol 提交具体依赖与替代方案后再变更底座；不得悄悄把“复用源码”变成从零重写全部前端。

## 3. 源码复用决策

上游入口：https://github.com/zotero/web-library 。官方 README 说明该单页应用可运行在其他网站，但通过 Zotero API 获取数据，默认示例是只读公共库。因此必须检查数据层耦合，不能假设只换 base URL 即可使用。

Luna 在 A 阶段固定上游 commit，记录以下表格，每项给文件路径、依赖、改造量的依据和处理结论：

| 区域 | 优先处理 | 接入项目数据 |
| --- | --- | --- |
| 集合树与分栏布局 | 复用组件或局部源码 | 工作区、参照库、发现库、研究集合 |
| 列表、排序、筛选、选择 | 复用通用逻辑，替换数据适配 | 论文条目与专利族分组 |
| 详情面板、标签、字段呈现 | 保留交互，重设字段 | 文档版本、来源覆盖、证据与人工历史 |
| 阅读器 | 先核对独立性与许可再决定 | PDF 页码、XML claim/段落定位 |
| Zotero 账号、同步、云端协议 | 不接入 | 由本地服务与既有身份模型承担 |
| 调查与运行控制 | 项目新增 | 既有 harness 任务、预算与结果 |

保留实际复用文件的版权、许可与来源，记录改动及上游版本；逐项核查子模块/依赖，不能凭项目名称推断全部文件许可证。许可证参考：https://www.zotero.org/support/licensing 。分发前完成依赖与许可清单，使用项目自身名称与标识。

首选保留上游可用的构建链，避免一开始迁移框架。只有独立抽取已证实更简单时，才选择轻量 React 构建；A 阶段记录理由。不引入 Zotero 后端、第二套检索引擎或第二套调查状态机。

## 4. 用户界面与行为

顶部为工作区、全局搜索、新建调查、导入、设置与当前运行状态。左侧为参照库、发现库、研究集合、调查任务、待人工处理；中央为列表/阅读/比较/调查与报告；右侧为所选对象详情；底部为可折叠运行面板。

### 4.1 对象与身份

- 论文按稳定文献身份展示，正文版本独立。
- 专利按有来源依据的 family 聚合，展开到 publication/version。族关系未知时保留未分组状态，不靠标题猜测。
- claim 指专利权利要求时，与报告的研究主张分开命名，例如 patent_claim 与 report_claim，不能混用 ID。
- 证据保留 evidence_id、document_id、version_id 与 locator。PDF 物理页和印刷页不同则并列说明；XML 保留 claim/段落定位。无坐标时只做页或段落定位，不伪造高亮框。
- 集合成员关系与 reference/discovery 身份分开；收藏不能改变冻结参照库。
- 无现成持久集合服务时，首版采用库/运行派生导航；新增自定义集合先经 Sol 判断是否属于必要接口，不直接写入旧业务表。

### 4.2 首版页面

| 页面 | 必须可用 | 不具备能力时 |
| --- | --- | --- |
| 文献库 | 类型筛选、列表、版本详情、来源/覆盖 | 显示空库、未索引、来源失败的不同状态 |
| 阅读 | 从证据跳到 PDF 页或 XML 段落、原文与译文区分 | 显示定位不足及原文入口 |
| 专利比较 | 选择公开文本，原文权利要求并排阅读 | 缺失权利要求明确标缺，不自动生成法律判断 |
| 调查 | 需求、参照版本、检索式与依据、角色任务、结果 | 无执行器则等待；不自动调用付费模型 |
| 报告 | 中文双出口、主张→证据→原文、标准导出 | partial 与待人工事项持续可见 |
| 人工处理 | 问题、对象、理由、决定、历史与重新打开原因 | 只展示服务支持的决定枚举与作用域 |
| 设置 | 模型/来源配置、凭据存在性、本地能力状态 | 不把离线协议测试显示为在线认证通过 |

新建调查先允许结构化填写/导入已有 ResearchSpec；自然语言规划复用既有角色协议，有执行器和调用授权才运行。不为实现聊天界面另建一套规划系统。

### 4.3 运行可见性

阶段名称由实际后端状态映射，展示规划、搜索、获取、解析/RAG、分析、核查、写作/导出；并非所有阶段都有独立事件，不生成虚假百分比。

面板显示 run_id、当前阶段、待办角色、来源成功/失败/截断、实际已知预算与未知用量。区分 completed 的执行状态与 partial 的覆盖状态。日志不得包含密钥、完整授权头或未经许可的文档正文。

## 5. 应用接口与安全边界

建议采用同源本地 HTTP API + SSE，Python 薄封装优先 FastAPI；新增依赖置于 GUI 可选安装组。只绑定 loopback，静态前端同源提供；限制 Host/Origin，写请求使用本地会话令牌，禁止宽泛 CORS。工作区由启动配置选定，浏览器不能提交任意磁盘路径。

前端只调用应用接口，不读数据库。封装层复用业务服务，事件记录只作传输/观察，不成为新的业务真值或 LangGraph 状态机。

以下为逻辑操作草案；Sol 与 Terra 冻结 schema 和路径后 Luna 才接真实接口：

| 逻辑操作 | 现有入口或需补齐处 |
| --- | --- |
| capabilities/config-status | 汇总 doctor、执行器、来源及凭据存在性，禁止返回密钥 |
| runs/list/status/result/artifacts | InvestigationService.status/get_result/get_artifacts |
| investigation/create/advance/resume | create_investigation/advance_investigation/resume_investigation；写操作串行 |
| api-run/advance | advance_api_run；沿用持久调用账本，不重置预算 |
| tasks/list | get_pending_tasks；角色输出沿现有校验提交 |
| review/list/decide | review_list/review_decide；先确认当前作用域，不混用旧 Harness 与 InvestigationService 的清单 |
| report/export | export_report；旧冻结事实不改写 |
| evidence/context/document | get_discovery_evidence 与 RagLibrary 公开方法；缺映射时返回定位不足 |
| library/list/import | 核对现有库公开接口；缺少只读列表可加最小应用方法，不在 HTTP 层散写 SQL |
| events | 状态快照加可重连事件；seq/run_id/type/time/payload；断档时重新取快照 |
| stop | 需核对并补齐合作式停止边界，不从 resume 方法推定已有取消能力 |

只读返回包含 schema_version；列表需分页。错误返回稳定 code/message/retryable/request_id，不把异常变为空列表。读写请求明确 run/workspace 作用域，人工决定带有效对象与版本；冲突返回可处理错误。重复启动/导出/人工提交的幂等边界须定义，双击不能生成重复付费调用。

后台执行线程/进程只负责调用和排队，不复刻调查调度。SQLite 服务对象在拥有它的工作线程创建和关闭，不能将现有连接随意跨线程使用。一个工作区只有一个活动写入者，读取与 SSE 不阻塞 UI。

停止语义：请求后停止领取新任务；已发出的网络调用按既有超时结束并计入账本，不承诺撤销已计费请求。达到安全边界后才显示 stopped；重开后根据持久状态恢复，预算不清零。若需要超出小范围的编排改造，Sol 报告缺口，不用前端假状态交付。

凭据首版沿用 api_key_env/既有本地机制，界面仅配置引用并显示存在性。若要求 GUI 粘贴并保存 key，属于额外凭据存储设计，不能存入浏览器 localStorage。附件按服务端文档 ID 解析到允许目录，拒绝路径穿越；HTML/Markdown、XML 和文件名按不可信输入处理，渲染时阻止脚本及外部实体。

## 6. 开发阶段与验收

| 阶段 | 交付 | Sol 放行条件 |
| --- | --- | --- |
| A 源码和接口评估 | 上游版本、复用表、能力表、接口合同 | 有真实源码依据；前后端依赖明确；许可证可追溯 |
| B 并行实现 | Luna 前端；Terra 本地服务与必要应用方法 | 共用合同，使用无网络 fixture；各自自检后交固定候选 |
| C 集成与独立验收 | 可运行 GUI、操作记录、失败修正 | 下列 G01–G08 通过或有明确阻断，不能以构建通过替代 |
| D 收尾 | 启动指南、验收报告、遗留项和下一步 | 当前范围完成即停止，不自动扩展功能或在线预算 |

G01：干净依赖环境可安装并在 Windows loopback 启动；构建成功、页面无阻断错误；不依赖开发者绝对路径。

G02：既有冻结案例在隔离副本/只读结果中展示论文与专利，partial 保留。选取有效报告主张→证据→PDF 页/XML 段落实际打开；失效定位显示明确错误。

G03：无网络合成运行从创建到角色处理、核查和双报告完成；mock 必须在界面与结果中标明。验证 GUI 调用真实本地应用服务，而非前端定时器播放状态。

G04：合作停止、断开重连、后端重启后的状态与恢复；不重复任务或清空预算。至少一项超时/失败不会显示成功；能力未实现不得把按钮置为可用。

G05：隔离工作区提交人工决定后重开仍在，原机器判断与历史可查；重复提交不产生重复有效决定。

G06：同冻结结果标准导出可打开，canonical 事实不变；界面下载文件确为服务产物。

G07：Host/Origin、令牌、目录越界、不可信文本、密钥回显的针对性测试；外部资料不能触发应用命令。

G08：浏览器实际检查三栏缩放、长标题、空数据、来源失败、键盘焦点和中文显示；核心操作在 1280×800 及更宽窗口可用。开发者工具无阻断错误；截图只是补充，需有实际点击和状态读回。

新网络研究和五厂商真实账号验收另列 pending，不阻断本轮离线 GUI 门槛，不标成通过。旧验收中可复用的未变证据不重跑；只运行新封装和受影响回归。

## 7. 停止条件与排除项

不启动企业监测、云端部署、多用户权限、桌面安装壳、自动更新或 GitHub 发布；不重建原参照索引，不修改科学事实/旧 run，不为截图补造结果。新依赖/公开源码获取可用于工程开发，但不含 EPO/OpenAlex 调查或研究模型调用授权。

同一故障两次修正无进展，Sol 先定位根因，再一次性下达修正。需要底座替换、扩大业务范围或新增真实调用预算时，携具体影响向用户确认。
