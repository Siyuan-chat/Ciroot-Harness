## F04：切工作区后文献库选择框为空（P2，需修正）

实际包截图首先观察到顶部文献库选择框空白。随后复制现有 headless 脚本到临时目录，在工作区切换末尾增加 DOM 当前选项与活动 scope 的一致性检查，稳定得到：

```json
{"workspace":"w2","library":"","collection":"all","storedLibrary":"l3","options":[{"value":"l3","text":"Library C · readonly"}]}
```

复现：原测试依次选 w1 下 l1/l2，再切 w2。w2 只有 l3；内部 scope/持久选择为 l3，控件却无选中项。真实 EXE 页面也出现同类空白。证据为 `context-probe/results.json`、`context-probe/context-selector.png` 和 `context-probe.log`；探针退出码 1。旧脚本仅检查 localStorage 的 workspace，不检查控件选中项，故旧通过结果未覆盖该缺陷。

源码原因：`frontend/app.js` 的 `saveView()`（19 行）把所有 select 都当草稿；`switchContext()`（144 行）修改 scope 后触发 `render()`；`render()`（32 行起）又保存旧 DOM，`restoreView()`（20 行）最终将旧库值写入新控件。旧值不在新 options 中时 select 变空。请求仍使用内部 scope，本轮没有发现后端串库，但用户看不到正在使用哪个库。

修正合同：上下文选择器由当前 scope 唯一驱动，不能被普通表单草稿覆盖；草稿必须按离开前的 scope 保存，进入后只恢复新 scope 的非敏感编辑字段。检查 workspace/library/collection、语言、搜索及分页筛选的状态归属，避免用简单清空所有草稿掩盖问题。不要改后端数据或旧 run。

定向回归：w1/l2 → w2/l3 → w1、同库分组切换、三语 round-trip、页面重绘后，DOM 选中值、实际请求头和保存的 scope 一致；草稿仍按上下文隔离，密钥不落盘。原 U06/U08 迟到响应断言保留。修正后重打包，再核对源码/dist/包内一致性。
