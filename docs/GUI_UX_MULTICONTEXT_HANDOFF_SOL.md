# Sol 交接：三语、布局、任务与文献库切换

日期：2026-09-25。状态：**设计交接，未批准在本对话继续修改产品。**

用户本轮要求通过命令行验收前端，重点为多语言、文字布置、layout 和底部 route；随后明确增加多任务/多组文献库切换，并要求只出方案交给 Sol。本文中的 route 按当前底部调查流程条解释；同时明确页面路由与任务上下文，防止二者混淆。

## 1. 目标与恢复入口

把现有桌面前端变成能在多个调查与多个文献库之间可靠切换的三语工作台。先保持数据身份与上下文正确，再改善布局和运行可见性。切换语言不修改科学原文，切换浏览库不改变已冻结调查，切换页面不启动或停止研究。

先读 GUI_HANDOFF_SOL.md、GUI_FRONTEND_PLAN.md、GUI_API_CONTRACT.md、最新 GUI_ACCEPTANCE.md、GUI_INDEPENDENT_REVIEW_20260924.md 与 DECISIONS.md 后续用户选择；发生冲突时以最新用户要求和实际源码为准。

当前前端已有独立文献选择身份与计数修正、离线样例、模型/来源凭据和 MCP 入口。本轮不重复要求开发已经存在的能力，不以旧报告中“尚未实现”替代源码核对。旧 F01/F03 的回归仍应保留。

本轮曾在用户补充“只出方案”前做前端实验，随后撤回。app.js、i18n.js、style.css 的恢复内容与本轮开始前已存在的打包资源一致，build.js 的模块清单也已恢复；新增实验模块已从 frontend 移出/移除，dist 按恢复源码重建。EXE、业务后端与冻结资料未改。本轮实验结果不能作为交付通过证据。

## 3. 信息架构：四个不同对象

| 对象 | 身份与作用 | 与其他对象关系 |
| --- | --- | --- |
| 项目工作区 Workspace | workspace_id；调查记录、运行账本、人工历史、报告 | 可关联多个文献库；一个项目含多个任务 |
| 文献库 Library | library_id；原始文献、版本、证据与索引的实体存储 | 可以被多个项目只读引用；独立库不能靠名字或路径混同 |
| 文献分组 Collection | collection_id + library_id；按主题/用途组织的成员集合或已保存筛选 | 同一文献可属于多组；分组不是索引副本，不复制 PDF |
| 调查任务 Run | workspace_id + run_id；冻结需求、参照快照、预算和进度 | 可从一个或多个库/分组选择参照；发现资料归属该 run 的独立发现集合 |

首版必须能切换多个实体库和多个任务，并能选库内分组；不要把“三个库名称都指向同一个列表”作为完成。多个实体库存在相同 document_id 时，用 library_id + document_id + version_id 解析；证据、附件也必须携来源库上下文。

跨库搜索作为显式范围选择：默认当前一个库或当前分组；选多个库时显示“跨 N 个库”。各库 independently 检索、返回来源和覆盖，聚合策略需说明；不同模型/维度不能混成同一个索引或盲比原始分数。第一轮实施可先交付单库切换，跨库检索进入后续明确子阶段，界面保持不可用而非静默搜索单库。

冻结参照保存 library_id、文档版本/集合成员快照、索引版本与允许使用范围。仅保存一个会变化的 collection_id 不足以冻结调查。切换浏览库不会改变旧 run 的参照；用户明确更改研究输入时创建新版本/新 run，旧结果不回填。

## 4. 页面布局

建议桌面骨架：

```text
顶部：项目选择 | 当前文献库/检索范围 | 搜索框 | 语言 | 新建调查
左侧：文献库与分组树 / 调查任务 / 报告 / 人工处理 / 设置
中央：当前页面内容（列表、阅读、比较、任务详情）
右侧：当前对象详情；宽度可收起，长标题与标识正常换行
底部：当前任务名 + 状态 + 覆盖 | 可折叠阶段路线 | 查看全部任务
```

项目与库选择不要都塞进原有 64px 顶栏。宽度不足时顶栏分成上下两行，上行为项目/操作，下行为库范围/搜索；标签用短标题，完整名称通过提示和可访问名称保留。

### 4.1 布局与文字规范

- 正文/表单 14–16px，导航 14px，元数据不低于 12px，标题 20–24px。技术长 ID 放次级文字，可复制，不作为唯一人类可读标题。
- 主列表显示题名、类型、年份/来源、覆盖与必要状态；右栏显示完整元数据。原文字段不通过 UI 语言重新生成。
- >=1200px：三栏；900–1199px：压缩导航，详情可收起/抽屉；850×600：可用双栏，详情通过明确按钮切换，主操作和底栏仍可访问；更窄浏览器回退单栏。
- 主列表与详情各自滚动；顶部不截断，底栏折叠后至少保留当前任务/状态。文字放大 125%/150% 时不重叠。
- 长题名、三语按钮和页头允许换行；不要用硬裁切隐藏主要动作。输入框内文字滚动不应被误判为整个 layout 溢出。
- 页内不展示无意义重复品牌眉题，中文/英文/日文排版保持同一信息层级。

## 5. 多语言的明确语义

语言是应用级 UI 偏好；切换语言不切项目、不切库、不切 run，不发送模型请求，也不改变报告输出语言。

### 5.1 翻译范围

翻译导航、按钮、工具提示、aria-label、空态、加载态、连接态、日期/计数显示、阶段名称和错误说明。动态字符串使用 `t('run.progress', {stage, count})` 一类消息结构，禁止按中文前缀随意替换整段内容。

不翻译论文题名、摘要、原文片段、报告正文、人工备注、用户研究问题、JSON schema/命令、稳定 ID。若标题恰好是“分析”“报告”等 UI 字典词，也必须保持原样。服务技术 code 原样可复制，旁边显示本地化解释。未知 code 显示通用说明与原 code，不编造原因。

中文→英文→日文→中文的 round-trip 必须保留选择、非敏感表单草稿、选中对象、页内展开状态与滚动位置。页面刷新只恢复合理的导航/草稿，不自动执行任务。

### 5.2 草稿与凭据

为研究问题、表单配置、人工备注建立按 workspace/run/page 分区的草稿；任务参数与人工意见不能写到另一个任务。普通草稿是否持久化明确标记，默认可恢复本地非敏感草稿。

密钥不进入 localStorage、URL、日志、截图或草稿持久层。切语言保留当前尚未提交密钥的策略可选择“仅受控内存保留”或“明确清空提示”，由 Sol 冻结一种行为；不能把通用保存所有 input 值的方案直接用于凭据。

语言切换仅重绘文案；后端状态刷新不应周期性替换整个正在编辑的表单 DOM，否则会丢光标、输入法组合和未提交文字。

## 6. 多任务与多库切换行为

### 6.1 当前上下文

集中管理 `{workspaceId, librarySelection, collectionId, runId, page, objectRef}`。当前检索范围与当前任务参照范围分开展示。选择器必须给人类可读名称，同时可查看稳定 ID。

每个 workspace/run 保留独立页签/草稿/展开/滚动状态；任务列表可搜索、按状态筛选和查看后台任务。首版先提供任务列表+当前任务选择，不要求实现无限页签管理。

### 6.2 切换顺序

1. 保存当前非敏感草稿与视图状态；正在编辑的决定保留草稿，不自动提交。
2. 增加 context generation，取消旧的读请求与事件订阅；已经发出的写操作仍归属原任务，不靠 AbortController 声称撤销。
3. 清空旧对象/结果/证据/错误的显示并展示新上下文加载态；不能先显示旧数据再换标题。
4. 读取新 scope 的能力、库/任务快照并订阅对应事件；只有响应的 scope 与 generation 都匹配时才更新当前视图。
5. 恢复该上下文视图状态。无权限/离线/库不存在时显示具体库的错误，不静默回退到默认库。

写操作使用开始操作时捕获的 workspace/run/document 身份，响应按原 scope 归档；用户在 A 点击导出后立即切到 B，A 的导出不能出现在 B 的报告列表。停止/恢复/人工提交同理。

缓存键至少包含 workspace/library/run、文档版本、查询与筛选条件、分页游标。请求 A 慢于请求 B 时，A 的晚响应不得覆盖 B。分页追加、检索结果和 evidence/file URL 都保持同一来源上下文。

### 6.3 执行并发

“支持多任务切换”不等于自动并发执行多个调查。首版建议一个进程只执行一个活动的变更任务，其余明确 queued/waiting；用户可以自由浏览其他库与已完成任务。原有工作区锁继续防止外部 MCP 与 GUI 同时写入。

这是有意的第一阶段限制：当前凭据会临时注入进程环境；若并发跨项目执行，可能发生凭据串用，必须先改为请求级凭据注入与执行上下文隔离才能扩大并发。不得仅修改前端让多个请求并发调用旧服务。

切走不会取消当前任务；关闭应用时对实际运行给出符合现有停止合同的状态；恢复不重置预算。队列状态属于薄执行调度，不复制 LangGraph 科学流程。

## 7. 底部 route：从示意图变成当前任务状态栏

建议底栏默认显示两层：第一层“当前任务名 / 执行状态 / 覆盖 / 等待事项”，第二层可折叠路线。未选择 run 时显示选择入口，不能为库浏览页面显示某个过期任务的进度。

当前真实 stage 的建议映射：

| 后端 stage | UI 标签 |
| --- | --- |
| planning | 规划 / Planning / 計画 |
| source | 检索与筛选 / Search & screen / 検索・選別 |
| acquire_normalize | 获取与解析 / Acquire & parse / 取得・解析 |
| analysis | 证据分析 / Evidence analysis / 証拠分析 |
| verification | 综合与核查 / Synthesize & verify / 統合・検証 |
| completed | 结果 / Results / 結果 |

当前核心把若干角色合并在 verification 中，不应虚构独立“写作百分比”。阶段由服务器映射，只有明确的阶段完成事件才显示完成勾；仅当前 stage 靠后不能推出所有前阶段成功。completed + partial 继续显示覆盖不完整，failed/stopped 不显示全绿。

路线项用有序列表及 `aria-current=step`，文字+形状共同表达状态；若可点击，只跳该阶段日志/证据，不重新运行该阶段。宽窗口一行六项，中窗口两行，折叠保留用户选择；语言/轮询/任务切换不能无条件重新展开。

底栏严格绑定 workspace_id + run_id。任务 B 页面不得保留 A 的路线；后台 A 有新结果时仅任务列表/通知点更新，不能抢占当前 B。切换任务时读回各自事件游标，不复用 global eventSeq。

底栏不超过窗口高的约 20–25%，小窗口可默认折叠；不以隐藏主操作来保全所有技术信息。详细账本与日志转到任务详情，底栏只呈现最关键状态。

## 8. 后端合同增补草案（尚未实现）

现有 workspace 在进程启动时固定；因此需要 Terra 提供注册层和上下文解析，不能由前端传任意绝对路径。

- 注册记录：workspace_id/name；library_id/name/read_only/index_status/association；路径只在本机后端注册配置中解析。通过可信本地配置或已验证本地目录选择流程添加，浏览器 API 请求只使用已注册 ID。
- 拟议 API：`GET /workspaces`、`GET /workspaces/{wid}/libraries`、`GET /libraries/{lid}/collections`，以及现有 run API 的 workspace scope、文献/检索/证据 API 的 library scope。由 Sol 冻结是否用路径或必填参数，不允许混用两套不一致惯例。
- 响应统一带 context、schema_version；未知/冲突 scope 返回稳定错误。所有 mutating 方法幂等键按 workspace/run/操作隔离，跨库附件请求必须校验其归属。
- RAG 实例以 library_id+索引版本管理，采用有上限的按需缓存；关闭旧库前等待其读取结束，不每次切库重新解析/索引，也不把所有模型/库无限留在内存。
- events/poll 的游标在 run 内独立，切换重建订阅；角色任务、预算、报告数据依旧由原有服务维护。
- 现有单库客户端保留兼容默认 scope 或版本化新合同；禁止用“默认回退”掩盖客户端传错 ID。Sol 选择一种明确兼容策略并测试。

## 9. Sol / Luna / Terra 分工与阶段

| 阶段 | Sol | Luna | Terra |
| --- | --- | --- | --- |
| S0 合同 | 冻结对象/切换/凭据/并发/route 语义，批准精确白名单 | 审计页面文案、断点与视图状态 | 审计多 workspace/library 服务缺口 |

沿用前端/后端单写所有权；Sol 不直接和执行者同时改产品。共享合同与 docs 决策由 Sol 唯一维护。本文件不授权在本对话发起代理；用户在另一个 Sol 对话发出实施指令后按以上阶段执行。

每轮一次完整任务、一次固定候选、自检后统一反馈；无变化不轮询。达到目标即交付，不自动扩大到新的科学调查或收费请求。

## 10. 命令行验收矩阵

使用 Playwright/Chromium headless，经命令行执行，禁止 Computer Use/鼠标桌面控制。两层验收分开：静态前端+显式 HTTP fixture 用于语言/布局/竞态；真实本地封装+临时工作区用于多库/运行持久行为。fixture 通过不冒称真实科学流程通过。

| 编号 | 场景与通过条件 |
| --- | --- |
| U01 | zh→en→ja→zh，导航/提示/动态计数/错误/aria 标签覆盖；参数、数值、ID 不变；不存在非原文的漏译 |
| U02 | 研究草稿、任务 JSON、人工意见、选择/焦点/输入法组合、展开状态在语言切换和后台状态刷新后保留；密钥不持久化 |
| U03 | 标题/原文为“分析”“报告”等字典同名词时保持原样；报告正文/命令/技术 code 不被 UI 翻译 |
| U04 | 1440×900、1280×800、1024×768、850×600；三语及 125%/150% 文字放大，无控件重叠/被裁/页面横向溢出，底栏可访问；窄屏回退可另测 |
| U05 | 两个项目、每项目至少两库、每库两个分组、三个任务；任务可有同名，库可含相同 document_id；列表/详情/证据/附件不串项 |
| U06 | A 请求延迟，切到 B 后 B 先返回、A 晚到；B 数据不变。A 写操作在 B 页面完成后仍只记到 A；快速 A→B→A 同样正确 |
| U07 | 从 A 库启动/创建参照快照，切到 B 浏览；A 冻结输入不变。分组成员随后变化不追写旧 run；只读参照不会因收藏变成发现库 |
| U08 | 当前 A run 的事件/底栏与 A 绑定，切 B 后显示 B；后台 A 完成不抢焦点；停止/恢复/partial/failed/未知 stage 明确，折叠状态保留 |
| U09 | 一个活动写入任务，其余排队/等待；切库仍可读；外部 MCP 写入冲突返回 busy；预算与幂等键跨重启保持，凭据不会跨项目混用 |
| U10 | 不可用库、空组、无结果、请求失败、权限不足分别显示；错误绝不悄悄退回默认库 |
| U11 | 最终源码 dist 和 EXE 内静态资源一致；命令行从最终包启动本地服务并完成相同范围操作。此项证明包内服务和浏览器渲染，不等于本轮重新验收 WebView2 原生窗口 |

布局检查用 DOM 几何量判断相交/溢出，并保存截图；不能只凭 CSS 搜索宣称视觉通过。动态语种扫描应排除有明确标记的科学原文，而非排除整张卡片以制造通过。

旧的全阶段 GUI 验收缺口仍保留；本次三语/切换验收不替代真实模型账号、跨文献科学效果或所有下载/原生阅读验证。
