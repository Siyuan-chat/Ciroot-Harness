# Terra 实现交接 D1

## 分工与当前任务

你负责另一个任务中的 Research Harness 实现。本设计任务负责需求、架构和最终独立验收。先做完整通用框架和文档落地，再返回这里进行测试验收；真实聚合物设计案例和带 demo 的 GitHub 发布在后续阶段。

不要仅生成目录和空类后报告完成。交付的是可安装、可运行的框架及可复现自测证据。也不要在没有真实资料/凭据时伪造案例结果。

## 必读顺序

1. [项目约定](../AGENTS.md) 和 [决策记录](DECISIONS.md)
2. [PRD](PRD.md)
3. [架构设计](ARCHITECTURE.md)
4. [数据契约](CONTRACTS.md) 与 [调查 Schema](../schemas/research-spec.schema.json)、[运行 Schema](../schemas/runtime.schema.json)
5. [验收标准](ACCEPTANCE.md)
6. [中文用户指南](USER_GUIDE.zh-CN.md) 及英文/日文对应版

用户最新明确要求优先。常规可逆实现选择自行决定；不要让用户重新回答已经确认的问题。需要改变产品行为时先说明具体冲突和影响。

## 必须保持的范围

- 通用领域配置；首个案例主题聚合物设计，不能把 AEM/某个聚合物或阈值写死到引擎。
- 自然语言 → 单问题澄清 → 版本化 JSON；输入格式和能力都校验；配置修改与执行意图区分。
- 首版本地、用户手动更新；内部流程自动；没有默认定时调度。
- 本地原文/索引/Embedding，允许必要证据片段发给配置的 LLM。
- 模型/API 来源适配；中英日完整用户路径。
- 证据缺口继续处理且累计到人工清单；人工单条决定不自动推广。
- 不预装网站/多租户/分布式平台，不绕过付费墙，不自动公开任何研究资料。

## 实现顺序

### M1：配置和需求入口
实现可安装包/CLI，ResearchSpec/RuntimeConfig 校验和版本存储、模型适配、chat/intake、doctor。参考 grill-me 的行为已写进 PRD，不依赖设计者机器上的个人 skill 文件。先保证用户手改配置不会被旧会话覆盖。

### M2：文档与证据
实现导入、不可变 raw、文档/版本/族身份、Docling/支持的 XML 解析、证据定位、SQLite、基准冻结、本地多语言混合 RAG。选择实际支持的 FastEmbed 模型并记录许可证；不要猜模型 ID。校验依赖缺失和单写入者行为。

### M3：调查编排与数据源
实现 LangGraph + 持久化，OpenAlex/EPO 适配、分页/认证/限流、来源子 agent 有界补查、共享预算、分级筛选/获取、增量与恢复。按来源分别记录完整性，不能把异常转成空结果。

### M4：分析、人工清单、报告
实现结构化判定、条件可比性、程序引用检查和模型核查、人工事件与 reopen、三语事实一致报告、技术地图、累计清单。完成自然语言 review/status/update 路径和显式 CLI 入口。

### M5：打包与交接
锁定验证过的依赖，完成三语使用指南、CI、测试夹具、诊断/错误文案、贡献说明和实现报告。版本/证据/限制写清。只有实际测试后才能把 README 的 design-only 状态改为 implemented alpha；不得写科学案例或真实 API 已通过，除非有对应记录。

每个阶段先跑必要检查再继续；不为小改动无限重复全量测试。测试重点见验收矩阵，使用能暴露错误的案例而非镜像实现。

## 工程自由度

文件布局、具体函数名、检索融合参数、内部数据库归一化由你选择。公共 JSON/用户可见语义保持一致。最小正确实现优先；公开接口、插件机制先于 fork 上游。若某候选依赖在当前环境不兼容，给出最小替代方案、实测证据及对契约的影响。

支持 Windows 当前环境；Linux 用 CI。CLI-only 首版足够，三语 HTML 是结果阅读入口。外部语音转写文本可粘贴进 chat；首版不用实现音频设备服务。

## 当前仓库注意事项

仓库初始化时没有提交、没有 remote。分派 Terra 前将设计包保存为本地初始提交，独立工作区从该设计基线开始。设计任务留下了 .gitignore 和 .env.example。被忽略的 .local/pre-handoff/pyproject.toml 是中断且未验证的草稿，不是依赖或架构权威输入；不要据此安装。当前没有产品源码或完成的环境。

不要读取其它项目资料补充本案例，也不要搜集/输出机器上已有密钥。实际凭据由用户按 env 名配置。没有凭据时完成离线契约与真实本地组件集成，把在线验证标为 pending。

两个任务共享资料时，Terra 是唯一产品代码写入者；设计任务只编辑规范和独立验收材料，规范变化需告知 Terra。根据 D13，Terra 按阶段提交检查点，设计任务在不可变提交快照上验收并直接回传反馈。明确未完成的工程工作继续推进；无需等待用户手动转交。尚未提交的改动不作为本轮验收对象。

## 交付与停止条件

1. 提交可运行框架、完整三语用户文档、包内资源、可运行测试和 CI。
2. 输出 docs/IMPLEMENTATION_REPORT.md，按验收 ID 列状态和命令，精确区分 fixture、本地真实组件、外部 API 和科学验收。
3. 说明数据目录、运行方式、未完成集成、已知风险和设计偏差；不打印凭据。
4. 返回设计任务独立验收，按直接收到的反馈继续修正；完整框架独立验收通过后停止本轮工作、暂停自动跟进。此时不做科学案例、不自动创建 GitHub 仓库或发布 demo。
