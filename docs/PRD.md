## 1. 产品目标与交付阶段

用户以自然语言说明关注的技术、指标和比较对象。harness 把需求转成版本化 JSON，在本地参照库基础上自主检索论文与专利、获取可访问资料、进行有证据的筛选和比较，输出技术地图、注目新进展及人工判断清单。

产品面向研究人员。默认通过本地 CLI 对话使用，程序 API 供将来界面复用。输入可以是文字或外部语音转写文本；首版不自建麦克风录音/语音识别服务。中英日能力适用于全文流程，检索数据源的语言覆盖另行声明。

## 2. 正常用户流程

1. 首次设置模型/数据源凭据及本地工作区；检测依赖和配置。凭据通过环境变量引用，不写进调查 JSON。
2. 用户描述需求。澄清 agent 读取已授权的配置与参照库概要，逐个澄清影响结果的歧义。
3. 形成有效 ResearchSpec，保存原始描述、回答、默认假设与字段来源；给用户可读摘要。
4. 用户明确要求调查/更新时执行。仅描述或修改需求先保存；无需强制增加每次确认页面。
5. 冻结本轮 spec、运行配置的非敏感摘要、参照库和检索起点。
6. 规划检索，按来源/技术分支派出子 agent。初筛候选，获取全文，提取证据，与基准比较并核查。
7. 生成本轮新增/变化报告、技术地图和累计人工清单。缺失证据不阻塞其它资料。
8. 用户可用自然语言或明确的 review 命令处理清单。人工决定作用于指定对象，并保留记录。
9. 后续手动更新复用当前 spec；修改需求生成新版本，对受影响资料重新判定。

## 4. 判定语义

- relevance：relevant / irrelevant / uncertain。
- metric_result：meets / does_not_meet / not_comparable / not_reported / not_applicable；每个指标独立。
- comparison_result：advantage / disadvantage / similar / different_approach / not_comparable / insufficient_evidence；不是法律新颖性判断。
- machine_disposition：include / exclude / watch。
- review：open / resolved / reopened；人工决定为 include / exclude / watch / request_more_evidence。
- 没有规定阈值的指标仅描述或相对参照比较。以“相对本库新增路线”表达进展，不声称穷尽全球文献或世界首次。
- 无关性有明确证据时可排除，即使性能数值缺失；与任务相关但关键证据不足时为 watch 并排队。
- 不把专利权利要求宣称的效果当成实施例已实证的结果；论文章节、专利 claims/description/example 必须区分。
- 核查 agent 也是模型判断；程序必须检查引文身份/原文匹配，最终科学准确率由独立人工集评价。

## 5. 人工清单

每项包括稳定 ID、文档/版本/专利族、问题类型、问题描述、相关证据、参照证据、机器建议、优先级依据、状态、人工决定/备注、创建/更新时间、事件历史。默认允许先观察，不阻塞本轮报告。

同一主题、同一文档、同一判定规则下的问题复用 ID；新证据内容发生变化时创建 reopen 事件。仅模型措辞变化不能反复打扰用户。人工决定不会因再次运行或翻译被抹掉。

自然语言处理含糊时，只问需要区分的资料或判断范围；不能把“这篇忽略”应用到全部专利族或整个技术路线。

## 6. 报告

- 本轮状态、时间、参照库/spec 版本、各来源成功/失败/截断情况。
- 新增和发生证据/判断变化的资料；相同资料再次命中不计新进展。
- 技术地图以可追溯分类矩阵开始，例如设计路线 × 已报告指标/机构/时间；未知项保留未知，三语同 ID。
- 注目进展包含重要性理由、相对参照差异、可比条件和证据缺口。
- 每个关键判断链接到本地原文与可用公开地址，显示页码/段落/表格位置。
- 人工清单包括本轮新增和累计未处理两种视图。
- 历史报告为本轮状态快照，不覆盖；人工更新后可生成新视图，注明其时间。
- 工程信息如哈希、模型版本、检索轨迹和成本放在单独 run manifest，不混入面向研究读者的正文。
- 翻译失败时报告 incomplete_translation，保留可用语言，不生成假三语全文。

## 7. 非目标与明确后移

首版不含默认定时调度、多人账号系统、独立 Web 应用、麦克风/ASR、云端托管、自动购买数据服务、付费墙绕过、正式法律意见、自动合成实验设计、化学结构式到分子图的可靠识别。真实结构式解析缺口进入证据清单，后续按案例需求扩展。

不强制全平台/全数据源支持；首版两种模型适配和两种数据源足以验证可插拔设计。不要一次性实现 Lens 或大量第三方库，以免扩大验收范围。

## 8. 质量与启动标准

- 文档中全部“支持”声明须能追溯到实现和测试；未实测外部能力标为 pending。
- 必须通过 [验收矩阵](ACCEPTANCE.md) G1/G2 后再进行科学案例。
- 运行时必须知道哪些问题尚无答案；不得把未知值置零。
- 除机器可验证的不变量外，不提前承诺科学准确率。G3 开始前由人工数据集确定并冻结评价标准。
