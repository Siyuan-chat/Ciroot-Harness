# 框架阶段范围审计

日期：2026-09-09。状态：审计结论与收敛建议；尚未宣称框架验收通过。用户要求重新审计现阶段是否过度推进，自动派发已暂停，实施任务已通知停止新增工作。保留已有代码、提交和验收证据。

## 结论

存在阶段范围过大和验收次序不合理的问题。用户的最终目标仍是可通过 API 配置使用的文献/专利调查 harness，但“先准备框架与文档”不必等同于“先把整个首版产品及全部集成做完”。原 D1 把真实本地 RAG、PDF/OCR、两类来源认证/分页/全文、两家模型、复杂恢复和科学判定等共同列为 G1/G2 门槛，推动了过早的全面集成。

责任在设计任务对阶段边界的定义。不能仅以 Terra 实现进度解释轮次增长，也不能把还没到阶段的能力统称为产品缺陷。上一轮“还需 6–10 轮”的估计基于这个过大的门槛，停止沿用。

## 审计依据

- PRD 的 G1/G2 同时要求可运行框架、实际依赖集成、恢复、人工判定及三语路径。
- HANDOFF_TERRA 的 M2/M3 要求真实 RAG、Docling、OpenAlex/EPO、认证限流、全文、增量与恢复全部实现。
- ACCEPTANCE 的 34 项场景混合了框架契约、集成质量、运行健壮性和真实组件验证，缺少逐阶段启用规则。
- 多轮实现都在打补丁，主干仍缺少统一演示流程。基础库/来源异常逐项检查有效，但在未建立演示主干之前持续修深层协议边缘，顺序不合理。
- 当前提交已到 cca8144；本次只记录边界，不对该提交作功能通过判定。自动化暂停不等于验收通过。

## 建议的阶段分配

| 能力 | 现在：框架 | 后续：接入与案例 |
|---|---|---|
| 自然语言 → JSON | 保留 ResearchSpec、累计修改、校验及版本边界；在当前 Codex 宿主整理需求并交给 harness；通过固定模型输出检验接收契约 | 独立 chat 客户端、两家模型实际适配与三语自然语言质量测试；不得把当前固定问答称为已支持 |
| 可插拔模型/来源/检索 | 定义必要接口、输入输出、配置与错误；至少一个明确标识的 fixture 实现经过主干调用 | 实际服务适配、认证、分页、全文、限流与供应商覆盖 |
| 本地资料 | 小型合成文本或规范化 JSON，reference/discovery 分离、冻结输入、证据 ID | 用户真实文献库、批量资料治理、真实 Embedding/Qdrant/LlamaIndex 检索质量 |
| 编排 | 实际调度主干串联规划、检索、分析、核查、人工清单与报告；fixture 提供节点数据，不能只返回固定最终报告 | 子 agent 自主补查、多来源并发、全部崩溃窗口恢复和持久化费用预留 |
| 解析 | 一个明确支持的简单输入格式，可定位文本证据 | PDF/OCR、跨页表格、复杂专利 XML、Docling provenance |
| 判断 | 保留原始证据、区分未知/不支持、检查引用归属；fixture 驱动验证状态流 | LLM 提取准确率、测试条件匹配、单位换算、技术优势的科学质量 |
| 人工与报告 | 一次人工决定持久化且不改全局规则；三语基础模板共用事实 ID；canonical JSON + 简单报告/清单 | 证据变化 reopen 全场景、真实进展排序、技术地图内容价值与翻译质量 |
| 健壮性 | 无密钥泄露、无虚假成功、原文/配置不被覆盖；单次预算上限与基本失败状态 | 全分页恢复、并发配额争用、增量水位、跨平台矩阵及性能规模测试 |

既有架构选型仍可作为接入阶段方向，不因为这次审计另造一套状态机或新增插件平台。框架的调度选型若采用 LangGraph，只需先验证最小图与业务服务边界；不要求所有重型解析/向量库同时安装。

## 建议的框架停止标准

1. 按文档可以安装和运行，公共 Schema 随包分发，配置只引用凭据名称；实际支持与未接入功能标注一致。
2. 给定有效 ResearchSpec 和小型合成参照资料，真实应用服务串联一次完整 fixture 流程，生成候选、带引用的判断、人工清单和报告；输入变化能影响输出。不是空类、占位回复或复制预制最终报告。
3. 修改配置产生可追溯版本，历史运行的配置、参照与报告保持稳定。用户手改内容不被旧状态覆盖。
4. 增加一个 fixture 来源或替换 fixture 模型时，只替换对应适配器和配置，不改业务主干；不预先建设任意 API 自动适配能力。
5. 一个坏输入或失败节点能得到明确失败/部分完成状态；未知数据不伪装成零、无结果或科学结论；一个人工决定能保存和重新读出。
6. 三语基础展示共享事实；所有演示标识 fixture/synthetic。交付一条可复制的演示命令和一份对应独立验收记录，通过后停止框架阶段。

“只要有 API 就即插即用”依然是后续接入和发布要证明的最终能力。框架阶段证明扩展接点和调用流程可用，不能提前把它宣传为任意真实服务已能使用。
